# ProtoOS — реестр утверждённых решений 01–19

**Базовая версия:** ProtoOS-TS-1.0, 2026-10-08. Все решения утверждены пользователем в ходе последовательного согласования.

| ID | Зафиксированное решение |
|---|---|
| 01 | GPT разрабатывает и проверяет ОС; исполняемое ядро автономно от GPT. |
| 02 | Полноценный системный эмулятор достаточен; запуск на физическом компьютере не обязателен. |
| 03 | Минимальная архитектурная полнота: два U-mode процесса, вытесняющее планирование, системные вызовы и аппаратная защита памяти. |
| 04 | Архитектура процессора — 64-битная RISC-V RV64. |
| 05 | Стандартная прошивка OpenSBI в M-mode передаёт управление S-mode ядру. |
| 06 | Монолитное минимальное ядро. |
| 07 | Ровно два настоящих процесса создаются статически при загрузке. |
| 08 | Один процессор (1 hart), вытесняющий Round Robin по таймеру. |
| 09 | Ошибка доступа U-mode процесса изолируется; процесс FAULTED, другой продолжает работу. |
| 10 | Системные вызовы `getpid()`, `yield()`, `exit()` через архитектурный `ecall`. |
| 11 | Статические физические страницы, отдельные таблицы Sv39, аппаратная изоляция. |
| 12 | UART-диагностика плюс независимые внешние доказательства через эмулятор/отладчик. |
| 13 | Режимы Normal (автономно) и Test (воспроизводимые испытания). |
| 14 | Один машинный образ; выбор Normal/Test во время загрузки без перекомпиляции. |
| 15 | Строгая повторяемая проверка, негативные тесты, независимые свидетельства и точные статусы. |
| 16 | Разработка на телефоне допускается без QEMU, но полная верификация только на настоящем системном эмуляторе. |
| 17 | Astra максимально автономна в пределах требований; ослаблять их или подменять ОС имитацией нельзя. |
| 18 | Git для истории; полные версионированные ZIP для переноса и контроля. |
| 19 | Единственная эталонная платформа: QEMU RISC-V `virt`, фиксируемые версии и параметры инструментов. |

**Контроль изменений:** любое изменение любого пункта 01–19 требует явного решения пользователя, записи об изменении и обновления версии технического задания. Никакой агент не вправе объявить изменение «простым инженерным уточнением», если оно меняет смысл принятого решения.

**Технические уточнения без нового решения:** конкретные регистровые протоколы ловушек, адреса памяти/устройств, номера вызовов, ISA flags, layout страниц и формат журналов выбираются исполнителем лишь при сохранении всех 19 решений и критериев приёмки.
