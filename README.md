# ProtoOS

[![acceptance](https://github.com/Intent-Forge/ProtoOS/actions/workflows/acceptance.yml/badge.svg)](https://github.com/Intent-Forge/ProtoOS/actions/workflows/acceptance.yml)

An experimental, deliberately minimal but architecturally genuine operating system for **RISC-V RV64**, running on **QEMU `virt`**.

OpenSBI (M-mode) hands over to the ProtoOS kernel (S-mode), which runs user processes (U-mode) with their own **Sv39** page tables, **timer-driven preemptive round-robin scheduling**, real `ecall` system calls, **interrupt-driven keyboard input** and a **page allocator**. Since v1.4 it **loads programs written in C** from a program archive given at boot, checks every file before loading it, and lets you run them from its command shell (Ctrl-C stops a program); every page a program used comes back. Since v1.5 it has a **disk**: a virtio-blk driver and a small flat file system (PFS) that keeps every file entirely old or entirely new when the system stops at any moment, programs to list, show, write and remove files, and programs started from the disk. It is a teaching/demonstration kernel, not a general-purpose OS.

## Features (v1.5)
- Monolithic kernel, ~5,700 lines of freestanding C11 and RV64 assembly; no libc. ISA: RV64IM + Zicsr + Zifencei, LP64, no floating point.
- **Programs in C (v1.4):** static ELF files in a cpio archive that the boot loader places in RAM (QEMU `-initrd`). The kernel checks the whole archive at boot and every program file before it allocates anything (segment permissions, addresses, sizes, no W+X), then loads it into its own address space with exact page permissions, a 16 KiB stack behind a guard page and a heap (`sbrk`); at most 64 pages per process. A small library (`print`, `read_line`, `malloc`, system call wrappers) and three programs: `guess`, `primes`, `clock`.
- **Disk (v1.5):** a virtio-blk driver for QEMU's virtio-mmio (version 2) devices, found in the device tree: full virtio 1.x initialisation, one request at a time, polled, every wait bounded; the device only ever reads and writes kernel buffers, never user memory. A timeout or device error stops the disk until reboot. A disk that cannot flush its cache is used read-only.
- **File system (v1.5):** PFS — up to 63 files of up to 128 KiB on a 1–64 MiB disk, flat names. A change writes the new data into free blocks, flushes, then writes the new directory into the second of two directory copies (sequence number + CRC-32) and flushes again; mount takes the newest valid copy. So after a crash, power loss or kill at any moment every file is entirely old or entirely new (within the fault model in [`docs/SPEC_V1_5.md`](docs/SPEC_V1_5.md)), and a file reported saved is on the disk. Every read checks the CRC of the whole file; a damaged disk image is refused with a precise code. Programs `files`, `cat`, `note`, `rm`; `run <program> <argument>`; a program not in the archive is loaded from the disk, with the same checks.
- **Memory:** a physical page allocator over the RAM above the kernel (31 232 pages of 4 KiB on QEMU `virt`); every page is zeroed when handed out and returned when its process ends.
- **Virtual memory:** an Sv39 root per process, 4 KiB user pages, disjoint user address ranges. Kernel pages and the page pool are mapped with U=0; each process's pages exist as user pages only in its own root; built-in programs are shared read-only. Guard pages below the kernel stack and the user stacks.
- **Processes:** up to 8. A (pid 1) and B (pid 2) are created at boot; the others are started with `spawn` (built-in programs) or `run` (programs from the archive) and ended with `kill`, `exit`, a fault or Ctrl-C; `wait` blocks until a process has ended and returns its status. States: READY, RUNNING, SLEEPING, BLOCKED (waiting for input or for another process), EXITED, FAULTED.
- **Scheduler:** round robin, 10 ms quantum, preemption by the S-mode timer (SBI TIME). A process that never yields is still preempted; a process waiting for input or sleeping uses no CPU time.
- **Interrupts:** S-mode timer and the UART receive interrupt through the PLIC into a 128-byte kernel input buffer.
- **System calls** (`a7` = number, `a0`–`a2` = arguments, `a0` = result): `read` (63), `write` (64), `exit` (93), `yield` (124), `getpid` (172), and ProtoOS-specific `sleep` (1001), `uptime` (1002), `procinfo` (1003), `spawn` (1004), `kill` (1005), `meminfo` (1006), `slotinfo` (1007), `run` (1008), `wait` (1009), `sbrk` (1010), `progs` (1011), and since v1.5 `fs_list` (1012), `fs_read` (1013), `fs_write` (1014), `fs_delete` (1015), `args` (1016), `run_arg` (1017). `read` and `write` check the whole user buffer against the caller's own page table before touching it (kernel pages, other processes' pages and guard pages are rejected with `-14`). Unknown numbers return `-38` and the process continues.
- **Shell:** `protoos.mode=shell` runs `proto>` in process A — `help`, `ps`, `uptime`, `echo <text>`, `attack` (asks the kernel to print B's memory; refused with `-14`), `run <worker|hello|counter|crash>`, `kill <pid>`, `mem`, and since v1.4 `ls` and `run <program>` for programs from the archive (the shell waits with the program in the foreground; Ctrl-C stops it; `run <program> &` starts it in the background); since v1.5 `run <program> <argument>` and programs from the disk (`ps` shows them as `(disk)`).
- **Fault isolation:** any other exception from U-mode (page fault, illegal instruction, …) marks only that process FAULTED and frees its pages; the others keep running. With nothing runnable, the kernel parks safely (timer off, `wfi`).
- **One image for everything:** the same ELF runs the normal mode, the demo and shell modes and every test scenario, selected by `bootargs`.

New in v1.5 (specified in [`docs/SPEC_V1_5.md`](docs/SPEC_V1_5.md)): the virtio-blk disk, the PFS file system, `fs_list`/`fs_read`/`fs_write`/`fs_delete`/`args`/`run_arg`, the programs `files`, `cat`, `note`, `rm`, and programs started from the disk; without a disk v1.5 behaves like v1.4. v1.4 ([`docs/SPEC_V1_4.md`](docs/SPEC_V1_4.md)) added programs in C loaded from a program archive, `run`/`wait`/`sbrk`/`progs`, Ctrl-C, the shell commands `ls` and `run <program> [&]`; v1.3 ([`docs/SPEC_V1_3.md`](docs/SPEC_V1_3.md)) added the page allocator, 8 process slots, `spawn`/`kill`/`meminfo`/`slotinfo`, built-in programs and the shell commands for them; v1.2 ([`docs/SPEC_V1_2.md`](docs/SPEC_V1_2.md)) added keyboard input through the PLIC, `read` with the BLOCKED state, `uptime`, `procinfo` and the shell; v1.1 ([`docs/SPEC_V1_1.md`](docs/SPEC_V1_1.md)) `write`, `sleep` and the demo mode. Earlier versions are tagged [`v1.4`](https://github.com/Intent-Forge/ProtoOS/tree/v1.4), [`v1.3.1`](https://github.com/Intent-Forge/ProtoOS/tree/v1.3.1), [`v1.2`](https://github.com/Intent-Forge/ProtoOS/tree/v1.2), [`v1.1`](https://github.com/Intent-Forge/ProtoOS/tree/v1.1) and [`v1.0`](https://github.com/Intent-Forge/ProtoOS/tree/v1.0).

Architecture, memory map and ABI: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md) ([Russian](docs/ARCHITECTURE_V1_RU.md)). Original frozen specification: [`TECHNICAL_SPECIFICATION_RU.md`](TECHNICAL_SPECIFICATION_RU.md), [`DECISION_REGISTER_RU.md`](DECISION_REGISTER_RU.md).

## What has been verified — and what has not
v1.0 defines 12 mandatory checks in [`ACCEPTANCE_MATRIX.csv`](ACCEPTANCE_MATRIX.csv): T1–T7 (S-mode boot, two U-mode contexts, timer preemption, `getpid`/`yield`/`exit`, Sv39 isolation, fault isolation, autonomous normal run) and N1–N5 (cross-process write, user read of kernel memory, privileged instruction from U-mode, unknown syscall, no runnable process). v1.1 adds T8 (`write`), T9 (`sleep`, including both processes asleep) and N6 (rejected `write` buffers), see [`docs/SPEC_V1_1.md`](docs/SPEC_V1_1.md). v1.2 adds T10 (`read` blocks without busy waiting and is woken by the UART interrupt), T11 (`uptime` against kernel time stamps), T12 (a scripted shell session), N7 (rejected `read` buffers) and N8 (input flood: 300 bytes into a 128-byte buffer), see [`docs/SPEC_V1_2.md`](docs/SPEC_V1_2.md); for these the harness types into the guest UART through a socket. v1.3 adds T13 (pages arrive zeroed even when reused), T14 (a spawned process gets its own root and pages and is scheduled), T15 (kill/exit return every page; a killed process never runs again), T16 (with several processes only the attacker faults), T17 (a scripted shell session with `run`, `ps`, `kill`, `mem`) and N9 (rejected `spawn`/`kill`, the slot limit, 200 spawn/kill cycles without a leaked page), see [`docs/SPEC_V1_3.md`](docs/SPEC_V1_3.md). v1.4 adds T18 (a C program is loaded page by page exactly as its ELF file says: permissions and contents of every page compared with the file), T19 (heap growth up to the 64-page limit), T20 (`wait` for exit, fault, kill, blocking), T21 (Ctrl-C ends the foreground program, also while it waits for input), T22 (a scripted shell session with `ls`, `primes`, the guessing game won by binary search, `clock` stopped with Ctrl-C), N10 (30 malformed program files, each refused for exactly its defect), N11 (13 malformed archives) and N12 (8 programs that break the rules fault alone), see [`docs/SPEC_V1_4.md`](docs/SPEC_V1_4.md). v1.5 adds T23 (the driver against the device: registers read physically, negotiated features, descriptors only at kernel buffers, the directory the kernel mounted equals that of an independent checker), T24 (file sizes 0 B–128 KiB written and read back, limits, a full disk, 135 directory updates; read-only disks change nothing), T25 (files survive a reboot exactly), T26 (a scripted shell session with `run hello world`, `note`, `cat`, `rm`), T27 (20 boots killed at random moments while files are being replaced: every file intact, one whole generation), N13 (22 malformed disk images, each refused with exactly its code, and a fallback to the second directory copy), N14 (bad names, lengths and kernel pointers refused; damaged files and programs give EIO) and N15 (no disk or a legacy device: every file call −19, everything else as v1.4), see [`docs/SPEC_V1_5.md`](docs/SPEC_V1_5.md).

Evidence is collected from outside the kernel, never from its own messages: the QEMU interrupt trace (`-d int`), GDB (privilege level, CSRs, registers, physical memory, an independent Sv39 page-table walk) and QMP sampling for the normal mode. Every boot directory under `evidence/` holds the exact QEMU command line, raw logs, observations and a per-check verdict. The normal-mode check (T7) is a 3 × 30 s bounded observation (~3,075 timer switches per run), not a proof of unlimited stability.

## Build and run
Tested on Ubuntu 26.04 and 24.04 under WSL2; any recent x86-64 Ubuntu/Debian should work.

```sh
sudo apt install qemu-system-riscv opensbi gdb-multiarch binutils-riscv64-unknown-elf \
                 python3 python3-venv build-essential
sh build-scripts/setup-zig.sh            # pinned Zig 0.13.0 (hash-checked) into ~/.protoos-venv
sh build-scripts/build-wsl.sh            # -> build/protoos.elf, programs, build/programs.img, build/disk.img + SHA-256
sh build-scripts/run-shell.sh            # shell with programs and disk: ls, run files, run note todo, run hello world, ... (quit: Ctrl-A, X)
sh build-scripts/run-scenario.sh protoos.mode=demo 8         # demo: processes print, B attacks A
sh build-scripts/run-scenario.sh protoos.mode=normal 10      # normal mode for 10 s
sh build-scripts/run-scenario.sh protoos.test=isolation 3    # A writes into B -> page fault
python3 validation/run_acceptance.py     # full acceptance, 3 clean boots per check (~7 min)
sh build-scripts/host-tests.sh           # host tests: Sv39 builder, DT parser, archive and ELF checkers, file system
```
On older Ubuntu releases QEMU for RISC-V is in `qemu-system-misc`. Other scenarios: `umode`, `preempt`, `getpid`, `yield`, `exit`, `kernel-read`, `fault`, `csr`, `bad-syscall`, `idle`, `idle-fault`, `write`, `write-bad`, `sleep`, `sleep-all`, `read`, `read-bad`, `read-flood`, `uptime` (the `read` ones wait for typed input), `mem`, `spawn`, `kill`, `multi`, `spawn-bad`; with a program archive as the fourth argument (`build/tests.img`): `elf`, `sbrk`, `wait`, `ctrlc`, `user-bad`. The shell keeps its files in `build/disk-session.img`, a copy of `build/disk.img` made on first use (`none` as the third argument: no disk). Released files only: `cp release/disk.img /tmp/disk.img; sh build-scripts/run-shell.sh release/protoos.elf release/programs.img /tmp/disk.img` (the shell writes to the disk image it is given).

## Not included (by design)
No folders, permissions, timestamps or file descriptors (the v1.5 file system is flat: one disk, 63 files of up to 128 KiB, each replaced whole), no disk cache or interrupts, dynamic linking, networking, drivers beyond the UART, PLIC and virtio-blk, SMP, POSIX or user-mode floating point. The crash safety is shown under QEMU and with a simulated faulty disk; real disks (SD cards, NVMe) are not claimed.

## How it was made
ProtoOS was built with AI assistance under the direction of the project owner: the specification and earlier stages with OpenAI GPT models, the v1.0–v1.5 kernel, programs, test harness and releases with Anthropic Claude; the v1.3, v1.4 and v1.5 code was also audited independently by OpenAI Codex. The owner set the goals and made the decisions; the frozen specification and the decision register record the AI roles as they were at the time.

## Кратко по-русски
ProtoOS — экспериментальная минимальная ОС для RISC-V RV64 под QEMU `virt`: ядро в S-mode, до 8 процессов в U-mode, у каждого свои таблицы Sv39, распределитель страниц памяти (страницы обнуляются при выдаче и возвращаются при завершении процесса), запуск и завершение процессов во время работы, вытеснение по таймеру, ввод с клавиатуры по прерываниям (PLIC), изоляция отказов, демо-режим (`protoos.mode=demo`) и командная оболочка `proto>` с командами `run`, `kill`, `ps`, `mem`, `ls` и др. (`protoos.mode=shell`, запуск: `sh build-scripts/run-shell.sh`). С версии 1.4 ОС запускает **программы на C** из архива, который передаётся при загрузке: ядро проверяет каждый файл до загрузки, даёт программе своё адресное пространство с точными правами страниц, стек и кучу; программу на переднем плане останавливает Ctrl-C. В комплекте игра `guess`, `primes` и `clock`. С версии 1.5 у ОС есть **диск**: драйвер virtio-blk и простая файловая система PFS (до 63 файлов по 128 КиБ), которая при остановке в любой момент сохраняет каждый файл целиком старым или целиком новым; программы `files`, `cat`, `note`, `rm`, команда `run <программа> <аргумент>` и запуск программ с диска. Все 42 обязательные проверки v1.5 (T1–T27, N1–N15) пройдены, по 3 чистых запуска каждая, на двух машинах; доказательства получены снаружи (трассы QEMU, GDB) и лежат в `evidence/`. При каждом изменении GitHub Actions заново собирает ОС, архив программ и образ диска (все побайтно совпадают с выпущенными) и прогоняет всю приёмку на QEMU 8.2.2. Не проверялось: реальное железо и реальные диски. Проект создан с помощью ИИ (GPT, затем Claude) под руководством владельца. Лицензия — AGPL-3.0.
